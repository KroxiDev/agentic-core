# Orquestar

1. Accept only the grammar `^(Orquesta|\/orquestar|\$orquestar)(?:\s+|$)`. Requests outside it remain direct and create no coordinator or agent.
2. Ask before starting only when the objective is missing or there are no verifiable acceptance criteria. If reason is absent, preserve the runtime value `not_specified` and do not ask for one.
3. For a new execution, invoke `agentic-core start` through the installed public seam exactly once, passing a JSON object with the literal activated `request`, an `intention` object, `changesExecutableBehavior`, and `planningNeedsHowDecision` through stdin or an exact `--input` file. `intention` is never text: it contains a non-empty `objective`, optional non-empty `reason`, and string arrays `constraints` and `criteria`; `criteria` must be non-empty. Validate that shape before invoking the seam, but never call `start` as a payload preflight. Capture and use stdout from that same invocation as the runtime result; never call `start` again to recover, persist, inspect, or preflight its output. Prefer stdin. If the host requires a transport file, place it temporarily below `.agentic-core/workers/transport/`, delete it immediately after the command, and never leave helper files in the product tree. Never import or call `startOrchestration`; only the public seam may start the runtime.
4. For an explicit resume request, invoke `agentic-core resume --run <runId>`. When no run id was supplied, invoke `agentic-core resume` and ask the user to choose from the returned list; never select one automatically. Continue only from the role and brief returned by the public seam.
5. Use the role supplied by the runtime result together with its brief. Never choose, reorder, construct, or reuse a role or brief yourself.
6. Map the role exactly as follows and invoke that installed profile directly with the host's native Agent/subagent tool: `Explorador`, `Planificador`, `Refactor`, and `Evaluador` -> `agentic-read`; `Implementador` -> `agentic-production`; `Tester` and `Verificador` -> `agentic-tests`; `Documentador` -> `agentic-docs`. Never infer a different profile from the current brief permissions, and never use a simulated or fallback product path. Before invoking `agentic-read`, require the host's actual read restriction plus its narrowly reviewed exact `quality_artifacts` exception; stop as blocked if the host exposes only instruction-level restraint.
7. Pass `JSON.stringify(brief)` exactly as the native agent prompt, without any prefix, suffix, summary, whitespace wrapper, or surrounding fence.
8. Load only the skills listed by the brief. `agentic-tdd` is valid only for an Implementador changing executable behavior, but its absence never removes test permissions granted by the brief. Use `agentic-grilling` only for a material ambiguity in the intention or when a Planificador faces a real HOW decision, not because reason is missing or `not_specified`.
9. After native invocation completes, use the exact complete final response from that single native invocation and forward its bytes without inspecting or changing them through the installed public seam: `agentic-core submit-handoff --run <runId>` with the response bytes on stdin, or `--input <path>` when the host requires an exact response file. Capture and use stdout from that same `submit-handoff` invocation as the only runtime decision; never re-invoke the agent or seam to recover or persist output. Prefer stdin; any required transport file must live temporarily below `.agentic-core/workers/transport/` and be deleted immediately after the command. Never parse, locate `{`, extract a substring, trim, remove a prefix, reconstruct, repair, or submit an object yourself. The seam alone validates the raw response and routes invalid responses through the runtime's single `protocol_retry` budget.
10. Treat the result returned by `submit-handoff` as the only next runtime decision. Continue only with its returned role and brief after `continued` or `protocol_retry`; stop on terminal status or request the missing input when instructed. If it returns `needs_mode_change`, ask for explicit user approval and invoke `agentic-core approve-mode-change --run <runId> --to <normal|full>` only after approval; never infer approval or call the runtime function directly. An observing harness must never run this loop.
11. Read Golden Rules only from `.agentic-core/golden-rules.md`; do not reproduce them in this skill, profiles, briefs, or adapters.
